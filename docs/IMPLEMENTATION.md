# 速览（Interpreter）

在每条回答下面加一段「说人话」的版本：先给结论，再分点讲清楚，整体约为原文的三分之一；事实、数字、路径、命令、代码原样保留。改写用哪个模型由你在块内菜单或设置弹窗里挑，跟主对话用的模型无关，也不会花主对话的上下文。

## 为什么不是加一句提示词

把「请说人话」写进主模型的系统提示词，看着更省事，代价却不小：每个模型都得单独调、每次请求都要多背一截指令（还常把它的 prefix 缓存打掉）、换模型就得重调一遍。速览走旁路：主模型的系统提示词、工具定义、上下文一个字都不动，解释是一次独立调用 —— 输入是这一轮已经落盘的回答，输出只进界面。主对话的上下文一个 token 都没多，改写失败也只是这一块空着。

## 它不动什么

- 原文还在上面，一个字都没改。
- Session 日志没有新增事件，会话记录和上下文都不受影响。
- 后面轮次的模型看不到这段速览，它只出现在界面上。

## 什么时候会出现

- 回答要有正文，且长度落在 `minChars`（默认 400 字）与 `maxChars`（默认 40000 字）之间。
- 纯工具轮次、没有正文的轮次，以及短于 `minChars` 或长于 `maxChars` 的回答，连「› 速览」这一行都不出现：点了也只会回一句「这条没什么可压的」，不如别放。判定由 Host 侧做（`POST /interpreter/probe`），一次本地请求、不调模型、不进缓存。
- 还要看此刻的模式：`全部` 每条都做，`本会话` 只做加入白名单的会话，`手动` 一条都不做，等你去点。模式按「当前会话」显示：本会话模式下，不在白名单里的会话显示为 `手动`；在白名单里的会话切回 `手动`，只把它自己移出白名单。
- 自动模式只管打开之后（以及本次启动 DSH 之后）新写出来的回答，且跳过被用户中途打断（`interrupted`）的回答。翻开旧会话时，以前的回答一律是收起的一行「› 速览」，点了才生成，不会补跑整段历史。同一时间最多 2 个改写在跑，其余排队。
- 若配置了 `dailyTokenCap`（大于 0），当天插件自身累计用量（含手动生成）达到上限后会停下，该轮收起为一行 `› 速览 · 今日额度已用完`，点开可看当日用量并通过「现在整理这一条」手动触发；手动点击不受额度限制，次日按本机自然日自动重置。
- 链接只认网页（`http` / `https`）、`file:`、`mailto:` 和本地路径；`javascript:`、`data:` 这类地址只留文字、不做成链接。
- 默认是 `手动`：装上之后，够长的回答下面只有一行「› 速览」，点一下才生成，不会自己花钱。用顺手了在右上角 `⋯` 菜单里切到「本会话」或「全部」。

## 第一次用

不自带模型。点开速览，点右上角 `⋯` → 「模型」（或进入「设置」弹窗），从列出的 provider / model 里选一个（列表就是这台机器上 `ctx.llm` 能用的那些）；没选之前点开只会提示一句，不发请求。选中之后这一条立刻重做，以后都按这个来。

挑模型时优先选「比喻多、先说结论」的那种：[Artificial Analysis 的 Metaphorical 榜](https://artificialanalysis.ai/evaluations/aa-personalitybench/traits/metaphorical)量的就是这个；同一张榜上的 Answer First、Bottom-Line Summary 也一样对口。干活用一个模型、速览用另一个，是最省心的搭配。

## 用法

### 回答下方的速览块

左边是一个「› 速览」的折线小三角，点它收起或展开这块内容。字体照着回答顶上那行状态文字来：15px、常规字重、次级色，折线图标中线与文字中线对齐。整块放在 `--dsw-alias-interactive-bg-hover` 的柔和卡片底色上（浅色模式下为浅灰块、深色模式下为微提亮卡片，避免浅色主题下 `bg-layer-*` 全白看不出边界）。

收起的时候只留一行 `› 速览 · 结论句`（中间圆点由样式绘制、垂直居中）：结论句取速览首段第一句，去掉 Markdown 记号后截断至 36 字加省略号（悬停显示完整句）。手动模式下未生成过的回答只有「› 速览」；探针结果回来前先不渲染，避免闪现又消失。

右上角收进一个 `⋯` 角落菜单，点开是单层不透明浮层卡片（空间够朝下弹，贴近输入框改朝上弹，避免被输入框遮挡）：
- **自动速览**：`全部` / `本会话` / `手动`
- **详略**：`普通` / `详细`（切完立即按新档重写当前块，其他块同步跟随；两档各自缓存，来回切换不重复计费）
- **语言**：`跟随原文` / `中文` / `英文`（三种选择各自缓存，首次生成与二次收紧均遵守）
- **提示词**：`基准` / `角色版（实验）`（两种内置写法各自缓存，切完只重做当前块；基准在跑用户自己的提示词时这一行显示 `自定义`）
- **模型**：列出本机全部可用的 provider / model，选中即保存并重做当前块
- 分隔线下是 **复制生成过程**（只在这一块已经生成完时出现，见下文「生成记录」）和 **设置**：后者收起菜单并弹出「速览设置」弹窗

正文底下靠右是一行小字和两个小图标：`2.5k tokens` 是这条改写实际花掉的 token；复制按钮把整段 Markdown 原文放进剪贴板，按下去图标本身立刻变成勾（失败时变叉），1.5 秒后复原，不会多出文字把 token 计数挤开；最右边环形箭头丢掉缓存重做这一条。悬停在 token 数上，提示框有两行：

- 第一行是用量，按读者能加起来的口径写：`输入 2393（缓存命中 1200） · 输出 1268（思考 900） · 合计 3661`。DSH 的 `inputTokens` 不含缓存读取，`outputTokens` 含思考，所以输入一项把缓存读写加回去，括号里另列缓存命中；输出括号里另列思考。没有缓存或思考时不写括号。
- 第二行是这条怎么生成的（`traceLine()`）：写法、版式、初稿多长、查出几处排版问题、调了几次、用的哪一稿，例如 `角色版 · 分块（原文 10 节） · 初稿 307 个词，1 处排版问题 · 按排版问题重写后 308 个词，用第二稿`。

改写进行中时，正文位置显示带扫光动画和逐次变长省略号（`.` → `..` → `...`）的「整理中」，遵循 `prefers-reduced-motion`。等了 10 秒（`QUIET_WAIT_SECONDS`）还没回来，后面接一段次级色的「已等 45 秒」「已等 2 分 5 秒」，每秒更新，用来分清是慢还是卡住了。

### 生成记录

每次改写，Host 都把过程记在 `trace` 里，跟结果一起返回、一起缓存。`⋯` →「复制生成过程」把它转成 Markdown（`traceText()`）放进剪贴板，可以和速览对着读：

- 写法、原文多长、预算多少（英文回答写成「个词」，和告诉模型的口径一致）；
- 代码定的版式：原文各节的标题，以及原样发给模型的那段版式说明。基准没有版式，只在原文末尾提问时记一条「另外告诉模型」；
- 每次调用：第二遍的指令原文、思考档位、结果多长、代码查出的排版问题（多条时逐条列出）、这次调用的 tokens；
- 最后用的是哪一稿；发生过第二遍时附上初稿全文。

记录里的小标题太长时截到 24 个字符（`MAX_TITLE_CHARS`）。英文标题在整词处截断，末尾的逗号、冒号之类去掉，所以模型看到的是「1. Create the project…」，而不是「1. Create the project di…」。

### 设置弹窗（速览设置）

通过 `⋯` → 「设置」唤起，复用宿主 `@deepseek-ai/dsh-client-ui-primitives` 的 `Modal` 与 `Button`，挂载在 `shell.overlay` 上，背景压暗、底层会话位置不动。

弹窗分三块紧凑排布，统一适配深/浅色主题：
1. **核心配置卡片**：自定义分组模型下拉框（替代原生 `<select>`，按 provider 分组、带勾选高亮、Esc 优先收起下拉不误关弹窗、自动去重 `provider/` 前缀）、`详略` 分段切换器（`普通` / `详细`）、`语言` 分段切换器（`跟随原文` / `中文` / `英文`）、`提示词` 分段切换器（`基准` / `角色版（实验）`）。
2. **提示词编辑区**：使用正文无衬线字体（`--dsw-font-family`）和细圆角滚动条，右上角实时显示字数（`当前 / 8000`）。选「基准」时编辑的是基准提示词，与内置原文不同时出现一键「恢复默认」；选「角色版」时框里显示角色版的内置原文，只读，标注「内置 · 只读」，用户自己的基准提示词原样保留。
3. **参数卡片**：
   - `触发字数`：`min` / `max`（原文字数范围）
   - `普通档篇幅`：`ratio` / `cap`（选「详细」档时柔和降不透明度，悬停或聚焦恢复可编辑）
   - `Temperature`：0–2 滑块与数值框联动
   - `自动日限额`：显示当日已用 / 不限状态 + 内嵌 `tokens` 单位的数值框
   - 四行参数的补充说明统一收进标签旁的 `ⓘ` 悬停/聚焦提示，不在界面上平铺长段解释。

底栏只放一个主按钮：无新改动时保持置灰不可点；有改动时亮起为「保存」（支持 `Ctrl/Cmd + S` 或 `Ctrl/Cmd + Enter`）；保存成功后变为置灰的「已保存」，弹窗不关闭。校验或请求报错固定显示在底栏上方，滚动后也不会漏看；按 `Esc`、点右上角 `×` 或点遮罩均可关闭弹窗。

## 配置

界面上的所有开关与设置弹窗里的每一项，均经 DSH 配置接口（`ctx.fiber.entry` + `configEditor`）写回**当前 profile 目录下** `cordis.patch.yml` 中 `- id: interpreter` 那一行的 `config`。

插件包自带的 `cordis.patch.yml` 仅作首次安装初始值；界面第一次保存后，profile 这一行会保存完整 `config` 并替代包内初始值。生效顺序为 `内置默认 → profile 该行 config`。删掉该行 `config` 即回到内置默认。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `provider` / `model` | `''` | 改写模型，须成对配置 |
| `mode` | `'manual'` | 自动触发范围：`manual` / `session` / `global` |
| `sessions` | `[]` | `session` 模式下的会话白名单（最多保留最近 200 条） |
| `length` | `'normal'` | 长度档位：`normal`（普通）/ `detailed`（详细，固定 `0.5` / `1600`） |
| `language` | `'auto'` | 输出语言：`auto`（跟随原文）/ `zh` / `en` |
| `variant` | `'baseline'` | 内置写法：`baseline`（基准）/ `roles`（角色版，实验） |
| `minChars` | `400` | 原文短于该字数跳过 |
| `maxChars` | `40000` | 原文长于该字数跳过 |
| `ratio` | `0.35` | 普通档目标字数占原文比例（`0 < ratio < 1`） |
| `capChars` | `900` | 普通档速览字数上限（不小于 150 的整数），按显示宽度算：汉字算 1，字母、数字和半角符号算半个 |
| `temperature` | `0.3` | 采样温度（`0`–`2`） |
| `prompt` | 内置 | 用户自己的改写系统提示词（1–8000 字），只替换基准 |
| `dailyTokenCap` | `0` | 自动模式每日 token 上限，`0` 为不限（内存按自然日计数，重启清零） |

### 内置提示词与用户提示词

- 内置提示词只放在代码里：`BUILT_IN_PROMPTS` 按 `variant` 存基准（`DEFAULT_PROMPT`）和角色版（`ROLE_PROMPT`）。实际用哪段由 `promptOf()` 决定：`variant` 是 `baseline` 且行里有用户自己的 `prompt` 时用后者，否则用所选内置。
- 行里只存用户自己的提示词。`persist()` 每次保存都会检查合并后的行：`prompt` 是任一内置原文（当前或历史）时直接删掉这个字段。设置弹窗每次保存都会把提示词一并发来，「恢复默认」发回的也是内置原文，所以这两种情况都不会把内置原文写进行里。
- 0.2.1 及更早的版本会把内置原文整段存进行里。识别靠 `PAST_BUILT_IN_PRINTS` 里的 SHA-256 指纹，比较前统一换行并去掉首尾空白。命中的行读取时按当前内置处理（`formOf()`、`promptOf()`、`ownPrompt` 都照此），下次任意保存时从行里删掉。**修改 `DEFAULT_PROMPT` 时，要把旧原文的指纹加进 `PAST_BUILT_IN_PRINTS`**，否则存着旧原文的行会被当成用户自定义。
- 角色版不开放编辑。路由以后会依赖各个内置写法的行为，被用户改过的副本没法跟着版本更新。

### 角色版的版式由代码决定

角色版的提示词只管内容取舍。分不分块、分几块、按什么顺序，都由 Host 代码在调用模型前决定，生成后再由代码检查。基准不走这套，只有一处例外，见下一节。

- **扫描**：`outlineOf()` 读原文的 Markdown 标题，跳过 ```` ``` ```` / `~~~` 围起来的代码，所以脚本里的 `#` 注释不算标题。出现两次以上的最高一级标题算作「节」：文章顶上单独一个标题不算一节，节下面的小节也不算。原文含 `<ask_user_question>` 转出的提问行，或去掉代码后的正文以问号结尾时（`asksReader()`），记为「在等读者做决定」。
- **定版式**：节数 ≥ 3（`MIN_SECTIONS`）且字数预算 ≥ 300（`MIN_BLOCK_BUDGET`）时分块。`layoutHint()` 在预算那句后面列出原文各节的标题，要求按这个顺序合并成 2–4 块，每块用 `####` 小标题。其余情况要求写成一句结论加几条要点，不用小标题。在等读者做决定时，分块的要求结论之后的第一块就写这件事（算在块数里，标题用要决定的事本身），不分块的要求结论之后先写；原文问读者的问题照原样列出，一个问题一条，不许改写成「补充……」这类陈述句，有选项和代价的一起留。
- **查排版**：`layoutCheck()` 只查版式，不碰内容，返回给模型的改法（`problems`）和用来比较两稿的扣分（`faults`）：
  - `layoutProblems()`，每条扣 1 分：第一行是不是标题；该分块时有没有小标题，块数是否超过 4（`MAX_BLOCKS`）；不该分块时有没有小标题；小标题是不是「结论」「待决」「操作」「参考」「证据」「过程」「边界」这类分类名（`CATEGORY_WORDS`）；有没有「常用组合：」这种只当标签用的短行（`leadIns()`，不超过 10 个字宽、以冒号结尾、下一行是表格或要点）。
  - **塞得太满**（`packedLines()`）：一段超过 3 句（`MAX_SENTENCES`）、超过 1 个分号或超过 120 字宽；一条要点超过 2 句、超过 2 个分号或超过 120 字宽。要点放宽到两个分号，是为了留住「延迟：LRU 纳秒级；Redis 约 1ms」这种带标签的对照写法。代码、标题、表格行不算，行内代码先抹掉，免得里面的 `;` 被数进去。所有这样的行合成一条改法，最多引用 3 处（`MAX_QUOTED`），其余写「等」；每行扣 1 分。
  - **碎得太多**（`crowdedBlocks()`）：一块超过 5 条（`MAX_BLOCK_LINES`），或不分块时结论之后超过 6 条（`MAX_FLAT_LINES`）。表格、代码块各算 1 条，开头的结论句不算。每块一条改法，要求说同一件事的并成一条、次要的删掉；按超出的条数扣分。这一项和上一项互相牵制：只查「塞得太满」时，重写会把每个分句拆成一条，一块拆出十几条。
- **修一次**：有问题就把这些改法连同草稿发回去重写一次。塞得太满的改法先要求「每处只留最要紧的一两件」，实在都要留才拆成两三条，留在原来那块里，不另加小标题。草稿同时超了预算的，同一遍里带上 `TIGHTEN.roles`；没超的，要求「除此之外内容不要增减」，删次要条目仍有余地。两版比较时，扣分少的胜出；一样多时取短的；再一样时留第一版。第二遍失败时保留第一版。排版没问题、只是超预算时，走和基准一样的二次压缩。
- 只有不合格的草稿才多花一次调用，合格的草稿仍是一次调用。

### 基准遇到原文提问

基准不给版式，也不查排版。但它的提示词只讲怎么压，实测会把原文结尾问读者的几个问题整段删掉，只读速览的人不知道对方在等自己回答。所以 `asksReader()` 判定原文末尾在提问时，基准也会在预算那句后面收到 `ASK_HINT`（问题照原样放在速览末尾，一个问题一条，不删、不改成陈述句）；超预算再压一遍时，指令末尾加上 `ASK_KEEP`。用户自己的提示词替换基准时同样生效。基准的提示词正文没改。

### 第二遍用最轻的思考档位

第二遍（重写或再压）只是照指令改一份现成的草稿，用不着多想；按模型默认档位跑时，实测它花在思考上的 token 能到初稿的十倍。所以第二遍会带上 `reasoningEffort`：`lightEffort()` 按 `off` → `minimal` → `low` 的顺序，取这个模型提供的第一个档位，每个 provider/model 只查一次。DSH 交给插件的 `listModels()` 不带 `reasoning` 字段，所以先用 `ctx.llm.resolveModelInfo(provider, model)` 读，旧版 Host 没有这个方法时才退回模型列表。模型不提供档位或读取失败时，不带这个参数，按模型默认跑。初稿始终用模型自己的默认档位。

实测 opencode-go 的 `deepseek-v4.1-flash` 在 `low` 档省得不多，第二遍的输出 token 仍和初稿相当。

## 它怎么变短

1. 每次请求都带上具体字数预算：`普通` 档按 `原文长度 × ratio` 并夹在 `150` 与 `capChars` 之间；`详细` 档固定用 `0.5` 与 `1600`。具体数字比「请短一点」稳定得多。
   - 长度按显示宽度算（`sizeOf()`）：汉字、全角字符和全角标点算 1，字母、数字、半角符号和空格算半个，换行不算。按字符数算的话，900 个英文字符只有一百五十来个词，英文回答的预算会被砍掉一半多，实测连原文给的 Windows 命令都被压掉了。预算、超预算判断、两稿比较、段落和要点的长度上限都用这个口径。
   - 原文以半角文字为主时（宽度不到字符数的 6 成，`inWords()`），告诉模型的是词数：`原文 1100 个词，速览请控制在 300 个词以内`，按一个词 3 个字宽折算（`SIZE_PER_WORD`）。再压一遍的指令和生成记录也用「个词」。
   - `minChars` / `maxChars` 两道门槛仍按字符数算，设置项的含义不变。
2. 若设定了固定语言（`zh` / `en`），会在用户消息末尾追加语言指令，覆盖默认「跟随原文」规则，且第一轮与二次压缩轮同时生效。
3. 首次结果超过预算 `1.5` 倍时，带着草稿自动再压一遍，取更短的一版（角色版的草稿没通过排版检查时也会再改一遍，取舍先比排版扣分，见上文）；第二遍用模型最轻的思考档位；两次调用的 `usage`（含缓存和思考 token）累加后上报。第二遍失败时保留第一版草稿，不整条报错。第二遍的指令按写法区分（`TIGHTEN`）：基准沿用「只留结论、必要步骤和风险」；角色版要求保留开头的结论句和各块小标题，只在块内删减，免得第二遍把第一遍留下的待决事项删掉，或把分好的块压回一整段。
4. 正文里若有主模型没调用成功、直接写成文字的 `<ask_user_question>` 标签（DSH 只渲染工具调用，不解析正文里的这个标签），`answerAt()` 读出原文时就把它转成文字：问题一行、每个选项连同说明各一行，去掉标签和 JSON。字数判断、预算和改写看到的都是转换后的文本。
5. 渲染直接复用 DSH 的 Markdown 排版规则和主题变量，表格、列表、引用、代码块与链接图标和原文保持同一套视觉体系。

## 实现

### Host 侧（`index.js`）

注册四个本地路由，全部声明 `auth: 'required'`：准入由宿主 `webServer` 在 handler 之前完成（凭据缺失 401、来源不受信 403、无准入决策 503），handler 只处理已登录请求，也不读未通过请求的体；三个 POST 路由仅接受 `application/json`：

- `POST /interpreter/rewrite`：按事件的 `data.turn` 与 `turn/start` 在当前轮次内提取落盘的 assistant 文本（不跨轮借用），经并发限流器（上限 2）调用 `ctx.llm.stream` 改写；角色版先由 `outlineOf()` / `layoutHint()` 定版式，生成后经 `layoutCheck()` 检查（见「角色版的版式由代码决定」）；第二遍经 `lightEffort()` 带上最轻的 `reasoningEffort`。返回 `{ text, usage, trace }`，`trace` 即「生成记录」。流以 `stop` 以外的原因结束一律判为失败且不缓存。缓存键为 `${provider}/${model}/${length}/${language}/${variant}@${revision}:${sessionId}:${seq}`（最多 500 条）；同一轮并发请求共享单次调用，仅当全部等待者断开连接才中止上游流。自动请求（`auto: true`）会额外检查 `interrupted`、`autoSince`（取 `startedAt` 与配置 `autoSince` 较大值）及当日 token 限额（`skip: budget`）。
- `POST /interpreter/probe`：读取同一份轮次日志判断是否满足正文存在与 `minChars`–`maxChars` 区间，返回 `ok` 或 `too-short` / `too-long` / `no-answer`；不调模型、不进缓存、不看 `autoSince`。
- `GET /interpreter/models`：枚举 `ctx.llm.listProviders()` × `listModels()` 及当前选中的 `provider` / `model`。
- `GET /interpreter/config`：返回 `mode`、`sessions`、`length`、`language`、`variant`、`live`、`tokensToday`、`tokenCap`、`defaultPrompt`、`builtInPrompts`（各写法的内置原文）、`ownPrompt`（基准是否在跑用户自己的提示词）及 `settings`（经 `formOf` 补齐默认值的表单字段；行里只有内置原文时，`prompt` 给的是当前的基准原文）。
- `POST /interpreter/config`：校验并持久化局部更新；白名单通过 `addSessions` / `removeSessions` 增量合并避免并发覆盖。全部 15 个配置字段（含内部 `autoSince`）均通过动态导入 `@deepseek-ai/schemastery`（声明于可选 `peerDependencies`）标记为 `.volatile()`，保存时就地更新、不重启插件；加载不到 schema 时自动退回重启模式并通过 `live: false` 上报。改动 `REWRITE_FIELDS`（`temperature`、`ratio`、`capChars`、`minChars`、`maxChars`、`prompt`）时递增 `revision`，使旧缓存与在途任务自然失效。

### Client 侧（`client.js`）

以单文件浏览器模块（`window.__ModuleLoader__.load`）向宿主注册两个 slot：

- `conversation.chat.turnTail`（`Interpreter`）：单轮速览块，内含探针缓存（`probes`，上限 500）、共享配置存储（`gateStore`）、`⋯` 角落菜单、轻量 Markdown 解析与安全链接过滤、扫光等待态、token 展示、剪贴板复制与重试/刷新。
- `shell.overlay`（`SettingsDialog`）：由全局 `settingsStore` 控制显隐，打开时并行拉取 `/interpreter/config` 与 `/interpreter/models`，本地先用 `readDraft` 校验再提交；保存成功后同步更新 `gateStore` 与 `savedModel`，让页面上已挂载的速览块立即可见新值。
- 样式表通过 `ensureStyle()` 单例注入到 `#dsh-interpreter-css`（全部挂在 `ra-` 前缀下，内容变更时覆盖更新），深/浅色均依托 DSH 主题变量，不引入外部样式表。
- 测试钩子 `window.__DSH_INTERPRETER_TEST__` 仅在单测环境启用，供 `test/client.test.js` 直接覆盖纯逻辑函数。
