# 速览调试记录

在 DeepSeek Harness 里实际跑速览，每轮看结果和「复制生成过程」里的记录，找问题、改、提交一个检查点。
模型：opencode-go · deepseek-v4.1-flash，详略普通（比例 0.35，上限 900 字）。

## 第 1 轮 · 检查点 2

**跑了什么**：角色版，「网页端与桌面版差异」会话里那条 HTTP 缓存回答（原文 4429 字，5 节）。

**记录**：预算 900，分块（5 节合并成 2–4 块），一次调用，初稿 1159 字，代码没查出排版问题，5408 tokens。

**看到的问题**

- 第一块是两大段：一段里用分号把 5 件事串成一句，另一段 4 句话。提示词写了「一条只说一件事，不用分号串」，但没有代码在查，模型照样这么写。
- 表格前有一行「常用组合：」，只是引子。（先记下，看后面几轮会不会再出现）
- 1159 字超了 900 字的预算，但没到再压一遍的 1.5 倍门槛。

**改了什么**

- `layoutProblems` 加一项检查：正文里一行用了两个以上分号，或一段超过 3 句、一条要点超过 2 句，就算「塞了几件事」，带着这一行的开头送回去拆成要点。代码块、表格行、行内代码里的分号不算。
- 新测试覆盖分号串句、长段、长要点，以及代码和表格里的分号不误报。

## 第 2 轮 · 检查点 3

**跑了什么**：重启 DSH 载入检查点 2，同一条 HTTP 缓存回答再跑一次角色版。

**记录**：初稿 1900 字（超预算 1.5 倍），代码查出 3 处「一段塞了 4 件事」，送回重写；第二稿 1124 字、无排版问题，用第二稿。两次调用合计 7.5k tokens。

**看到的问题**

- 新检查生效：初稿里分号串句和 4 句长段都被抓到，重写后拆成了要点。
- **bug**：第一次调用的 tokens 显示「输入 7 · 输出 973 · 合计 3924」。DSH 的 `inputTokens` 不含缓存命中的部分（这次 2944 个 prompt token 命中了上一轮留下的缓存），`outputTokens` 又已经包含思考，插件只显示输入和输出，几个数加不起来，像是算错了。
- 「常用组合：」这种引子第二次出现（初稿里是「以下是常用组合：」），重写也没去掉。
- 「代码查出的排版问题」多条时挤在一行，难读。

**改了什么**

- tokens 改成能加起来的写法：「输入 2951（缓存命中 2944）· 输出 973（思考 N）· 合计 3924」，悬停提示和生成过程记录都用这个。Host 把 `reasoningTokens` 留下来并在两次调用间相加。
- `layoutProblems` 加一项：不超过 10 个字、以冒号结尾、下面紧跟表格或列表的行，算引子，要求删掉。代码块里的 YAML 键不算，以冒号结尾但说了内容的长句也不算。
- 生成过程记录里多条排版问题分行列出。

## 第 3 轮 · 检查点 4

**跑了什么**：同一会话里更早那条「网页端与桌面版差异」回答（原文 1104 字，没有分节，带一张对照表和编号列表）。先跑角色版，再切基准，再切回角色版，最后点「重新整理这一条」。

**记录**：角色版预算 386 字，不分块，初稿 561 字，无排版问题，一次调用，「输入 1148（缓存命中 512）· 输出 1010 · 合计 2158」。

**看到的问题**

- 交互都正常：悬停提示两行都在；基准和角色版各自缓存，切回角色版不再调用模型；重新整理会重新调用。
- 提示词和检查打架：角色版提示词写着「表格和代码块前面要有一句话说明它是什么」，「常用组合：」正是模型照这句写出来的；上一轮加的检查又要它删掉。
- 重新整理出来的版本末尾多了一条「已按本机安装版……的文档核实」，是原文的出处说明，对读者用处不大。（先记下，不是代码能稳妥判断的事）
- 两次都超预算（561/386、1159/900），但都没到 1.5 倍门槛。

**改了什么**

- 提示词改成：小标题已经说清表格或代码块是什么时直接给；没说清就用一句完整的话交代，不要只写「常用组合：」这种标签。
- 检查的指令跟着改：小标题已经说清就删掉这一行，没说清就换成一句交代内容的话。
